# スコープ × 指示 2軸 A/B 実験(2026-08-20)

## 目的

小規模 agentic モデル(InternScience/Agents-A1-4B 級)に「fast-apply + anchoredit」で編集能力を付与するための設計判断:
1. `<code>` に**全文**を渡すか、**最小ブロック**(import ヘッダー + 変更 hunk ± 5 行)を渡すか
2. `<update>` に**コード snippet**(ファインチューニング分布内)を渡すか、**自然言語指示**(分布外)を渡すか

## 設定

- 同一 20 件(`harness/cases.json`、Kortix/FastApply-dataset-v1.0 test split 層化抽出)、同一エンドポイント(ローカル FastApply-7B、`temperature=0`、`FAST_APPLY_TIMEOUT=180000`)
- ブロック抽出: `harness/block.mjs` が GT の行 diff(LCS)から機械抽出。不変条件「`block_final` を `block_original` の範囲に splicing すると GT が再現」を全 20 件で検証済み
  - 注: データセットは末尾改行が不整合(original 15/20 件が末尾改行あり、final はなし)。diff は末尾空白除去後に実行し、ブロックが EOF に届く場合のみ末尾差をブロックに折り込む。ブロックがファイル中央のケースではファイル級 EXACT は末尾改行差のみで落ち得る(WS 級は影響なし)
- ブロックサイズ: 全文の 8%(case 13: 16/162 行)〜 FULL SPAN 6/20 件(小文件或変更が広範)
- 実行結果:
  - A: `results/2026-08-19T22-53-44-539Z/`(= validateStructure 修正後のベースライン)
  - B: `results/2026-08-20T01-01-18-070Z/`
  - C: `results/2026-08-20T01-10-29-791Z/`
  - D: `results/2026-08-20T01-19-46-167Z/`
- 自然言語指示: `harness/instructions.json`(20 件手書き。コード本文を含まず意図のみ記述)

## 結果

|---|---|---|---|---|
| ファイル級完全一致 | **13/20 (65%)** | 9/20 (45%) | 3/20 (15%) | 3/20 (15%) |
| ファイル級 WS 一致以上 | 13/20 (65%) | **15/20 (75%)** | 3/20 (15%) | 3/20 (15%) |
| ブロック級 sim ≥ 0.95 | 17/20 (85%) | 17/20 (85%) | 10/20 (50%) | 15/20 (75%) |

| parse 通過 | 19/20 | 20/20 | 20/20 | 20/20 |
| 中央値レイテンシ | 38.9s | **18.2s** | 18.3s | 38.0s |

## 発見事項

1. **スコープ効果(A→B)は温和**: ブロック渡しでファイル級 EXACT は 65%→45% に低下するが、sim ≥ 0.95 は 85% で不変。WS 一致以上はむしろ 75% と上昇。失敗例は「同じ行集合だが挿入位置が違う」が中心(case 0: `.hover-scale` を誤ったセレクタ内に挿入 — 省略マーカー + 繰り返し構造行での位置合わせ失敗)。逆にブロックで正しくなったケースも存在(case 9, 18: 全文では誤り/拒否だったもの)。
2. **コスト効果は明確**: ブロック渡しでレイテンシ中央値 39s→18s(約 2 倍速)、入出力トークン -43%。agentic ループ(1 編集 = 1 呼び出し)では直接メリット。
3. **自然言語指示(A→D、B→C)は決定的に劣る**: EXACT 65%→15%(全文スコープでも!)、sim ≥ 0.95 は 85%→75%(D)/ 50%(C)。fast-apply-7B はコード snippet へのファインチューニングが効いており、NL 指示は**分布外として致命的**に扱ってよい。
4. **両効果はおおよそ直交**: NL の劣化はスコープ無関係で発生。つまり「ブロック + コード」は「全文 + コード」の 7〜8 割の精度で 2 倍速・トークン 43% 減という合理的なトレードオフであり、「NL」はいずれのスコープでも採用しない判断材料になる。

## agentic モデル付与(ToDo 5)への含意

- エージェント(4B 級)が生成する `update` は**コード snippet の形式**である必要がある(自然言語では fast-apply が壊れる)。エージェントに求めるとは「対象ブロックを特定し、変更箇所 + 前後コンテキスト + `... existing code ...` 付き snippet を書く」こと。
- ブロック渡しを採用するなら: ① import/直列ヘッダーを含める(本案のブロック抽出ルール) ② hunk 周辺 ±5 行程度のコンテキスト ③ anchoredit anchor の一意性確保(小ブロックは MULTIPLE_MATCHES 得 → agent は anchor を明示指定すべき) ④ 挿入位置の曖昧さを避けるため、変更 hunk に隣接する固有行を snippet 冒頭/末尾に含める。
- **Agents-A1-4B は既に FASTCONTEXT エンドポイントで serve 済み**(インストール先 `.env` の `FASTCONTEXT_MODEL`)→ 実機ループ(e2e)の環境は整っている。
- 補足: B の 9 EXACT のうち 5 は FULL SPAN ケース。真のブロック適用(14 ケース)での EXACT は 4/14 (29%)。FULL SPAN の 6 ケースを除いた「実効ブロック」比較では B 優位性はやや過大評価気味に注意。

## 再現

```bash
node harness/fetch-cases.mjs 20        # 20 件抽出
node harness/block.mjs                 # ブロック抽出 -> cases-block.json
npx tsx harness/run.mts --mode full-code --timeout 180000
npx tsx harness/run.mts --mode block-code --timeout 180000
npx tsx harness/run.mts --mode block-nl  --timeout 180000
npx tsx harness/run.mts --mode full-nl   --timeout 180000
```
